# Doom Launcher 667 1.0.0-rc.11

- Fix genuine map completions being discarded after loading a save from a previous
  engine session. The tracker now captures the current launch identity during
  engine initialization and retains it in its non-serialized static handler.
- Save-restored CVars no longer replace the reporting identity. The importer still
  requires the exact current session token; stale events remain rejected.
- Fix direct resume paths: validated save names are now relative to `-savedir`,
  avoiding an engine-generated duplicate absolute Windows path. Managed sibling
  and imported-save folders are retained; save files are not moved.
- Retain the stable helper filename and existing saves, archives and database
  schema. No reset or database replacement is required.
- Add repeatable real-engine tests for both warp commands, save/load without an
  exit, genuine exits after loading in the same session or after an engine restart,
  and direct `-loadgame` starts. Each case also tests SQLite import and repeat import.

## Update

Validation: [18 requested cases plus 3 direct-resume cases passed](../testing/1.0.0-rc.11-tracking.md),
including real SQLite import and repeat import for each case.

Close the launcher and back up your portable installation before copying the new
program files over the existing installation. User databases and Data files are
not shipped. Do not reset. This remains a Release Candidate. The conservative
[tracking limits](../personal-library-and-multiplayer.md) remain unchanged.
