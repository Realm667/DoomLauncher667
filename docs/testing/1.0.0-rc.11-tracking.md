# RC11 tracking verification — 2026-11-08

Result: **18/18 requested cases passed**, plus **3/3 direct startup-resume cases**.
Every case used real engine events, imported its log into a fresh SQLite database
with the production importer, then repeated the import. All database results
matched the engine evidence; repeat imports were idempotent.

| Case | GZDoom | UZDoom | LZDoom |
|---|---|---|---|
| `map` warp | Pass | Pass | Pass |
| `changemap` warp, no intermission, target actually loaded | Pass | Pass | Pass |
| Save/load, no exit, same process | Pass | Pass | Pass |
| Genuine exit after save/load, same process | Pass | Pass | Pass |
| Load a previous-process save, no exit | Pass | Pass | Pass |
| Genuine exit after loading a previous-process save | Pass | Pass | Pass |
| Direct `-loadgame` startup followed by a genuine exit | Pass | Pass | Pass |

Negative cases produced no credited completion. Positive cases credited only
MAP01, under the new process's launch token and only after the actual engine exit.
Session A's saved token was not accepted as session B's identity. The importer
still rejects foreign-session events; the fix does not weaken this check.

The direct-start tests exposed and verified a related Windows path correction:
`-loadgame` now receives a validated path relative to `-savedir`, preserving
managed sibling/import folders instead of duplicating an absolute drive path.

Tests ran with already installed engines and the owner's legal Doom II IWAD in
isolated temporary folders. No engine configuration, existing saves, mod archives
or live launcher database were modified. Engines/IWADs are not distributed with tests.
Run the opt-in `--verify-map-tracker-regression` command documented in the feature
guide to reproduce the seven cases for an engine. Raw logs and JSON results are
written to the printed temporary directory.
